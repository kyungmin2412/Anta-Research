# 개별 기업 분석 탭 — 진행 상황과 남은 일

사업보고서 **본문**을 읽어 재무제표에 없는 지표까지 뽑아내는 화면.

## 지금까지 된 것

`/analysis` 탭. 기업을 고르면 최근 5년 정기보고서를 회계연도별로 묶어 보여주고,
사업보고서 원문을 받아 본문 표에서 지표를 읽는다.

| 단계 | 파일 | 상태 |
| --- | --- | --- |
| 정기보고서 목록 | `lib/reports.ts` | 됨 |
| 원본 ZIP → 목차·표 | `lib/report-doc.ts` | 됨 |
| 표 → 지표 | `lib/report-metrics.ts` | 됨 |
| 여러 해 합치기 | `lib/report-analysis.ts` | 됨 |
| 화면 | `app/analysis/[corpCode]/` | 됨 |

읽는 지표: 해외 매출 비중, 가동률, 제품 가격변동 추이, 수주잔고, 종속회사별
매출·순손익. 재고자산 추이도 `/analysis` 화면에 같이 둔다(이건 본문이 아니라
재무제표 API 값이라 파싱은 필요 없다).

## 회사별로 맞춘다

한 회사의 보고서 양식은 해마다 거의 그대로다. 그러니 모든 회사에 통하는 만능
파서를 먼저 만들 필요가 없다. **회사 하나를 잡고 그 회사 표에 맞추면 그 회사의
5년치가 한꺼번에 풀린다.** 회사를 늘릴 때마다 매핑을 하나씩 더하는 쪽이 훨씬
빨리, 훨씬 정확하게 간다.

- **공통 뼈대** (`report-doc.ts`) — 원문 받기, ZIP 풀기, 표를 격자로. 회사와 무관하다.
- **표 찾기** (`report-metrics.ts`) — 머리글 문구로 표를 짚는다. 지금은 공통 규칙만 있다.

매핑을 못 만든 회사는 그 지표를 비워 둔다. 억지로 추정하지 않는다.

## 원본 형식 (확인 완료)

삼성전자 2023년 사업보고서(접수번호 20240312000736)로 확인했다.

- ZIP 안에 본문 XML 한 개 + 첨부 두 개. **본문 파일 이름이 접수번호와 같다.**
- 인코딩은 **UTF-8**. EUC-KR 처리는 필요 없었다.
- 표는 HTML 과 같은 `TABLE`/`COLGROUP`/`THEAD`/`TBODY`/`TR`/`TH`/`TD`.
- 병합셀은 `ROWSPAN`/`COLSPAN`.
- 목차는 `SECTION-1` > `SECTION-2` 안의 `TITLE`. "II. 사업의 내용" 으로 잘라낸다.

덫 두 개를 만났다.

1. **표가 중첩된다.** 주석과 진짜 표를 한 칸짜리 표로 한 번 더 감싼다. 바깥
   껍데기까지 표로 세면 주석 글이 머리글에 섞인다. 안쪽 표만 고른다.
2. **주석 속 연도를 기간 칸으로 세면 열이 밀린다.** "2023년부터 …" 같은 문장이
   머리글 칸에 들어 있다. 칸 **전체**가 "제55기"나 "2023년"일 때만 기간으로 본다.

단위는 표 안이 아니라 바로 앞 한 칸짜리 표에 `(단위 : 억원, %)` 로 적힌다.
앞 문단까지 같이 훑어야 읽힌다.

## 지표별로 짚는 자리

| 지표 | 찾는 법 | 비고 |
| --- | --- | --- |
| 가동률 | 머리글에 "가동률" | 기수별 칸이 여러 개일 수 있다 |
| 해외 매출 비중 | 첫 칸에 내수·국내와 수출·해외가 함께 | 비중만 쓰면 단위를 몰라도 된다 |
| 제품 가격변동 | 머리글·소제목에 "가격변동", 원재료·매입은 제외 | 숫자 대신 글로 적는 회사가 있다 |
| 수주잔고 | 머리글에 "수주잔고/수주총액/수주액" | 수주산업만 싣는다 |
| 종속회사 실적 | 머리글에 "종속기업명"+"매출액"+"순손익/순이익" | "III. 재무에 관한 사항" 주석에 있다, 사업의 내용이 아니다 |

## 검증 상태

두 회사, 두 업종으로 확인했다.

**삼성전자 2023년 사업보고서** (제조업)

- 가동률 5건 (74.9 / 66.7 / 100.0 / 100.0 / 70.2%) — 원문과 일치
- 지역별 매출 3개년, 해외 비중 88.0 / 89.5 / 88.9% — 원문 금액과 일치
- 제품 가격변동 — 삼성전자는 숫자 대신 "전년 대비 4% 상승" 이라고 글로 싣는다.
  글에서 숫자를 뽑아 단가처럼 그리면 속이는 셈이라, 칸 전체가 숫자일 때만
  숫자로 본다.

**휴젤 2026년 반기보고서** (제약·바이오)

- 이 회사는 가동률·해외매출·가격변동·수주잔고 표가 아예 없다 — 업종상 자연스럽다.
  카드가 깔끔히 빠지는 걸 확인했다.
- 대신 연결재무제표 주석에서 종속회사 7곳의 매출·순손익을 읽었다. 휴젤아메리카
  당기 매출 327.4억·순손실 49.7억, 전기 매출 239.6억·순이익 30.7억 — 원문 표와
  한 자리도 안 어긋난다.
- 덫: 이 표는 캡션이 "① 제 26(당) 기 반기"처럼 정규식에 안 걸려서, 다른 소제목이
  먼저 캡션으로 잡히는 일이 있었다. `ReportTable.context` (표 앞 문단 전체)를
  따로 훑어 당기·전기를 가르는 식으로 고쳤다.
- 덫: 회사 이름 끝의 각주 번호("(*1)")가 표마다 붙는 공백이 달라, 그대로 두면
  같은 회사가 당기·전기에서 다른 이름으로 갈려 표가 두 줄로 쪼개졌다. 이름 끝의
  각주 번호를 지워서 고쳤다.

**아직 못 한 것**: 수주산업(건설·조선)의 수주잔고 표. 서비스업의 "표가 전부
없는 경우"는 휴젤로 확인됐지만, 수주잔고 자체가 실제로 읽히는 회사는 아직 없다.

### 분기보고서의 종속회사 노트는 실제로 있다 — 그리고 누적치다

처음엔 분기보고서(1·3분기)엔 이 노트가 없을 거라고 보고 아예 빼놨는데, 틀렸다.
실제 휴젤 1분기보고서 화면을 보면 "제 26(당) 기 1분기" 표에 종속기업별 자산·
부채·매출액·분기순손익이 그대로 실려 있다.

문제는 매출액·순손익이 **분기 단독 실적이 아니라 사업연도 시작부터의 누적치**라는
점이다(반기보고서의 "반기순손익"이 1~6월 누적인 것과 같은 이치). 그래서:

- 사업보고서(연간) + 반기보고서뿐 아니라 분기보고서(1·3분기)까지 받아 오도록
  `getBodyMetrics` 를 넓혔다(`MAX_QUARTER_DOCUMENTS`).
- `SubsidiaryFinancialRow` 에 `quarterIndex`(1~4, 사업연도 안에서 몇 분기
  시점까지의 누적인지)를 추가했다.
- 분기 단독 실적 = 이번 시점 누적 − 직전 분기 누적. 2분기 = 반기 누적 − 1분기,
  3분기 = 3분기 누적 − 반기, 4분기 = 연간 누적 − 3분기 누적. 1분기는 그 자체로
  이미 단독 실적이라 손대지 않는다.
- 사업보고서(연간)는 연간 총액도 그대로 남겨 둔다. 3분기 자료를 못 받아 온 옛날
  연도까지 값이 비어 버리는 걸 막기 위해서다. 3분기 자료가 있으면 "N년 4분기"
  라는 별도 열을 하나 더 만들어 연간 총액 옆에 나란히 보여준다.
- 직전 분기 원본을 못 받아 왔으면(예: 조회 기간 밖) 억지로 추정하지 않고
  비워 둔다.
- 합성 픽스처(1분기 누적 → 반기 누적)로 뺄셈이 정확히 맞아떨어지는 것까지
  확인했고, 이후 휴젤 2024년 1분기보고서(접수번호 20240514000693) 실제 원문으로도
  확인했다. "① 제 24(당) 기 1분기"/"② 제 23(전) 기 1분기" 두 표가 나란히 실리고,
  머리글도 "종속기업명/자산/부채/매출액/당기순손익"으로 예상과 같았다.

### `MAX_QUARTER_DOCUMENTS` 가 너무 작았다

휴젤 화면에서 "2024년 1분기"가 안 보인다는 제보로 위 문서를 실제로 받아봤다.
표 자체는 멀쩡히 파싱됐는데, `getBodyMetrics` 가 최근 분기보고서 **4건**만
받아 오고 있었다 — 2026 1분기·2025 3분기·2025 1분기·2024 3분기, 딱 여기까지.
2024년 1분기보고서(2024.05.14 접수)는 다섯 번째로 최신이라 이 4건에 못
들었다. 사업보고서·반기보고서는 5개년치를 받는데 분기보고서만 2개년치였던
셈이라, `MAX_QUARTER_DOCUMENTS` 를 4 → 10(사업연도당 두 건 × 5개년)으로
늘렸다.

## 남은 일

1. **건설·조선 한 곳** — 수주잔고 표가 실제로 읽히는지. 지금 코드는 머리글
   문구만 보고 있어 열 구성이 다르면 빈손으로 나온다.
2. **지역별 매출 표가 내수/수출로 나뉘지 않는 회사** — "국내 / 미주 / 유럽" 처럼
   지역만 늘어놓으면 지금은 아무것도 못 읽는다. 틀린 값을 내는 것보다는 낫지만,
   회사별 매핑을 붙일 첫 자리다.
3. **원본 캐싱** — 사업보고서 5건 + 반기보고서 4건 + 분기보고서 10건까지 매번
   받는다. 한 건에 600KB 안팎이라 페이지 단위 `revalidate` 로 버티고 있는데,
   분기보고서를 10건으로 늘려서 한 페이지에서 최대 19건을 받을 수 있다.
   느려지면 접수번호별로 따로 캐싱한다.

## 원본을 다시 받으려면

```bash
curl -o sample.zip "https://opendart.fss.or.kr/api/document.xml?crtfc_key=$DART_API_KEY&rcept_no=접수번호"
```

접수번호는 `/analysis/<고유번호>` 목록의 원문 링크에서 `rcpNo=` 로도 보인다.
